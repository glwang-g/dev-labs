# DevLabs · 开发者成长实验室

通过递进工程任务，让近乎零基础的学生先具备初级开发工程师入职能力，再形成跨技术栈迁移能力。

当前版本：**S0–S2 本机单学员 MVP**。使用一条 JavaScript 订单服务路线，将预测、实现、工程交付与能力证据串起来。尚不代表完成就业训练。

## 启动

需要 Node.js **25.8 或以上**及 Git。无第三方运行依赖，无需 npm install。

```sh
cd /Users/wangguanglei/work/dev-labs
npm start
```

打开 http://127.0.0.1:4317 。停止后重新启动，草稿、工程文件与证据仍保存在本机。`PORT` 可更换端口，`DEVLABS_DATA_DIR` 可指定独立学员数据目录；同一个目录只运行一个服务实例。

## 学生与教师工作台

右上角“学生 / 教师”切换工作台，默认学生侧；选择保存在当前浏览器。学生侧提供学习路线、学习日志与参考练习，教师侧提供学习概览、学习记录、试教记录与人工复核。同一浏览器内切回各工作台会回到上次页面，完整路线的函数/答案草稿和进行中的考核保留，切换前保存工程文件并取消自动前进。试教表单与复核备注在切换时暂存，刷新不承诺恢复未提交的教师备注。

教师概览只读显示当前本机学员的完整路线训练覆盖、考核、补练和提示记录。点击“学习详情”或某单元的“查看详情”，可查看训练/补练的逐次代码、预测、工程快照、提示量及失败检查，并查看多次已结束考核。进行中考核不展示本次作答和检查结果。

教师可以按单元或已结束考核记录追问、学生表现与实际帮助，再选择对应概念安排 1–5 项补练。学生在路线与学习日志收到反馈和待办，通过新题号/数据的真实验收；失败可重试，同题重复请求不累计通过数。补练达到要求后等待教师追问，教师可记录“已展示理解”或再开一轮补练；前后尝试与历轮结论均保留。

自动考核、教师观察与补练复核相互独立：教师确认不会直接改写单元/阶段通过状态；机器要求的针对性补练可由真实完成的教师补练满足，但独立考核仍需学生亲自通过。指定补练不打断正在进行的考核，也不作为全路线前进的额外人工审批门槛。三阶段全部 13 个单元共用这一流程。

新版本开始保存逐次作答与考核历史。升级时可保留仍在本机的最近一次旧考核，标注历史快照缺失；无法恢复此前已被覆盖的考核或未保存的旧训练代码，不生成虚构记录。导出包含已结束考核和训练的安全快照、教师观察与补练记录；不导出进行中考核的答案、评分或未来题目。旧体验路线观察与提交复核继续保留。

这是本机视角切换，未提供账号认证、权限隔离或多学员管理。导航配置集中在 `public/workspaces.js`，后续可由账号会话决定可用工作台；身份与访问权限仍需由服务端实现。

## 默认学习路线

默认入口为 **S0–S2 学习路线**：13 个能力单元下，既有 45 个训练位拥有稳定的最小 Lab 标识和独立链接；同概念变式仍属于重复练习，不代表 45 项不同能力。能力地图可直接进入任何单元和 Lab，也可跟随零基础推荐路线。

**进入学习与取得能力记录分开**。直接进入且缺少匹配的近期前置能力记录时，提供两道可跳过的入口诊断；结果只用于推荐帮助和桥接 Lab，不增加训练覆盖、不记录单元/阶段通过。匹配的单元独立考核记录在 90 天内可免重复诊断；较早记录仅触发可选热身，不作废既有通过结果。诊断题目前覆盖有限前置概念，不能替代全面分级测评。

需求、函数契约、代码与运行按钮连续排列。题目旁提供“输入与示例”和“本题知识点”浮层；完整输入结构、规则和公开示例也可在代码下方展开，默认收起。公开样例由独立教学资料定义，不读取隐藏验收用例。训练时点击查阅才记录知识点使用次数，不改写代码、不计为考核通过；教师可分别查看知识点查阅与提示次数。独立考核保留必要的题意、输入输出说明和公开示例，但不提供知识点浮层或查阅接口。代码预测题不公开当前程序的正确输出。

Lab 操作区按状态显示“开始练习”、进行中提示或“再练一次”，作答中的题目直接使用下方运行按钮。学习方式与本关链接收进“学习方式与分享”，切换方式不更换当前题目；能力验证单独说明剩余练习及考核条件。入口检查可选择直接开始练习，无需跳过后再点一次开始。

按需探索完成一个 Lab 后停留；推荐路线保留可取消的自动推进。桥接后可返回原 Lab。各 Lab 保存原题、草稿、最近运行与诊断进度，切换或刷新可以恢复。普通 Lab 的函数/答案草稿保存在本机服务，并在浏览器即时备份；尚未确认的诊断答案与独立考核草稿仍依赖当前浏览器。进行中的独立考核可“保存并离开”，探索后再恢复原题；暂停期间也不公开本次答案与评分。

阶段综合考核按钮不可用时，悬停约 120 毫秒、点击/点按或键盘聚焦显示同一条原因提示；点击不会发起考核，按 Esc 或点其他位置关闭。按钮下方文字也说明不可用原因：本阶段还有几个单元未通过独立考核，或当前仍在另一场考核中。普通不可用按钮使用正常鼠标指针，真正执行请求时才显示进行中状态。

单元能力仍需完成训练覆盖与独立考核，阶段仍需通过所有相关单元和综合考核。失败后按薄弱点补练，再重新考核；练习答对不会直接记录阶段达标。范围与限制见 [路线覆盖说明](docs/ROUTE_COVERAGE.md)。

旧版九关及条件分支样板保留为独立参考，不与新路线合并计算通关。下面的九关操作说明适用于“体验路线”。

## 体验路线

| 阶段 | 三个任务 | 验证方式 |
| --- | --- | --- |
| S0 程序认知 | 变量状态、取消订单分支、循环独立变式 | 必须先预测，再真实执行；保存首次与后续尝试、解释 |
| S1 语言应用 | 营业额、客户分组、门槛统计独立变式 | 每题四组输入，覆盖空数组、取消项、临界值和特殊客户名 |
| S2 工程基础 | 文件持久化、HTTP 查询、Git 交付 | 真实多文件 Node 工程、跨实例读取、实际 HTTP 请求、全量回归及干净提交 |

- S0 明确为只读观察；S1/S2 才开放代码编辑和恢复初始代码。完成方式按教学用途分配，不只按题目难度分配。
- 当前草稿与最近验收一致且完成本题要求时启用“下一任务”；阶段末进入下一阶段，最后一题进入学习日志。修改预测、代码、选择答案或必需解释会使旧验收或提交不再作为当前前进依据。
- 运行结果和解释提交在刷新、返回任务后恢复；帮助按需展开，顺利完成无需请求提示。
- 可编辑代码与分文件工程，草稿自动保存；恢复初始代码需要明确确认。
- 分级提示按需展开，独立变式与延迟复测关闭平台内提示和 AI。
- 基础练习答对即自动记录完成；概念题用简短选择检查；独立验证和工程交付才要求解释。解释字数只作完整性检查，不作能力评分。
- 每次验收保存源码摘要、代码或工程快照、结果、解释和截至当时的累计帮助量。
- 首次有效提交 7 天后开放同任务延迟复测，不自动安排通知。
- 本机人工复核页和 JSON 证据导出；复核记录明确标注未验证教师身份。
- 可选的兼容 Chat Completions 协议的 AI 提示接口，不自动覆盖或运行建议。
- CodeMuseum 与 xshow 作为外部理解资源链接；没有修改它们的代码或接入其私有执行服务。

## 主动推进的关卡体验

进入后定位上次未完成关卡；已完成的旧关卡会让位于下一未完成关卡，并用短暂高亮提示当前位置。基础题、概念题和解释任务在有效完成后默认自动继续，保留“先留在本题”。

同一阶段全部任务提交通过后，显示一次彩纸庆祝和 5 秒倒计时，默认进入下一阶段。可立即进入，也可选择“留在本阶段回味”；停留选择保存在本机记录中，刷新不会强制离开。切到后台时阶段倒计时暂停。最后阶段完成后自动进入学习成果，不跳往尚未实现的 S3。

阶段记录仅表示本阶段训练任务已提交通过，理解证据仍可稍后复核。未完成解释、只运行通过或缺少其他关卡时不会触发阶段通关。阶段进度与选择持久保存，旧关卡不会重复庆祝；减少动态效果设置下不播放彩纸动画。

## 按教学用途决定完成方式

| 方式 | 当前任务 | 完成后的操作 |
| --- | --- | --- |
| 直接通过 | S0 变量状态、S1 营业额统计 | 无需解释或再次提交，答对展示结果 2 秒后自动前进 |
| 简短检查 | S0 取消订单、S1 客户分组 | 运行通过后选择一个概念判断，确认正确后自动前进 |
| 解释提交 | 两个独立变式、三个 S2 工程任务 | 说明关键判断与验证依据，提交通过后自动继续；阶段末先庆祝，再默认进入下一阶段 |

自动前进可以点击“先留在本题”取消；手动导航、编辑内容或切到后台也会取消。刷新、返回已完成题目不会突然自动跳走，仍可查看上一题和手动继续。

同一轮（上次有效完成之后）累计两次运行或概念检查未通过时，改为要求简短复盘；复盘提交后恢复常规练习方式。延迟复测始终保留解释。本机服务独立执行这些规则，前端不能通过伪造完成类型跳过概念检查或工程解释。

证据明确区分基础练习、简短检查和解释提交；前两类不因没有解释而被标为缺失证据，也不会逐题进入人工复核队列。旧记录和已有解释保留，不进行批量改写。

## 工程练习

首次启动会创建 `.devlabs/order-service/` 和独立 Git 练习仓库，初始提交只发生在这个练习目录。平台页面提供真实的测试、status、diff、log 与 commit 操作；也可以打开该目录，在自己的编辑器和终端操作。

```sh
cd .devlabs/order-service
npm test
npm start
```

S2 各 Lab 当前共用同一个订单练习仓库与 Git 历史；进入和返回不会自动回滚整个工程。HTTP Lab 依赖可用的 store 模块，缺少时可进入文件持久化 Lab 补足。恢复草稿发现文件已在其他 Lab 改变时，优先展示最新文件，并提供旧草稿回看；每 Lab 独立工程环境是后续能力。

订单服务端口为 4318，平台端口为 4317。练习数据保存在工程的 `data/` 下，不纳入 Git；测试只创建和清理自己的临时数据目录。验收脚本与启动器由平台维护，可阅读但不能通过编辑器修改；平台重启会恢复这些支持文件，保留三个可编辑文件。

S2 使用内置模块和 JSON 文件，聚焦模块、测试、HTTP、持久化与 Git 的第一条交付路径。第三方依赖管理、数据库、部署、多人协作与陌生企业仓库仍是后续训练，不因这三个任务通过便宣称具备完整 S2 或入职能力。

## 可选 AI

默认不请求任何模型。未配置时显示“AI 服务未配置”，内置提示仍可使用。

启动前在终端环境设置 `AI_BASE_URL`（以 `/v1` 等接口前缀结尾）、`AI_MODEL`、`AI_API_KEY`，或使用你自己的环境变量管理工具。`.env.example` 仅说明变量；应用不自动加载 .env 文件。不要提交密钥。

学生明确点击后才发送当前代码、任务与问题到配置的服务。密钥只留在服务端，不进入学习证据或前端。每任务最多 10 次请求；失败也计数；超时 25 秒且不自动重试。AI 提示未经正确性认证，教师仍需检查是否越过提示边界。真实提供方尚未验收；测试使用本机明确的模拟接口，不消耗模型额度。

## 使用边界

这是本机、可信学员的教学 MVP，不是可直接公开部署的多租户代码沙箱。运行器采用独立进程、Node 权限、内存限制和超时；S2 为真实 HTTP 测试开放网络权限。这些措施不能防御恶意源码，Node VM 与权限系统不应被视为敌对代码安全边界。不要将服务绑定公网或用于接收陌生访客代码。参考 [Node 权限说明](https://nodejs.org/api/permissions.html)。

验收用例可读，学习记录可以被本机操作者修改；平台关闭 AI 无法证明没有外部 AI。测试通过、人工复核和延迟表现分别呈现，不生成“已掌握”总分或认证。S0 重试与同题延迟复测也可能受记忆影响，应配合教师现场新变式。

## 项目结构

- `server.mjs`：本机服务、记录持久化、执行、Git 和可选 AI 适配。
- `lib/curriculum.mjs`：九个任务与三阶段定义。
- `lib/teaching-service.mjs`：完整路线作答快照、考核归档、教师观察及补练复核。
- `public/teaching.js`：教师学习详情与学生反馈。
- `lib/checks.mjs`、`lib/code-runner.mjs`：函数验收与独立进程执行入口。
- `public/`：无构建依赖的响应式界面。
- `templates/order-service/`：真实工程任务模板和集成测试。
- `tests/`：隔离的端到端服务测试。
- `.devlabs/`：本机学员数据，不纳入版本控制。

产品分工：CodeMuseum 负责语言探索；xshow 负责机制实验；DevLabs 负责任务训练与能力证据。实现参考了两个项目的真实运行、草稿恢复及明确触发等设计，当前逻辑独立实现，避免复制整个应用和提前建设共享框架。
