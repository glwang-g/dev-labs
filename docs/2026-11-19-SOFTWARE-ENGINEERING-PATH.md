# 从 0 到 100 的软件工程成长路线

2026 年 11 月 19 日，整理今天 09:30（北京时间）起的 DevLabs 对话。本文把本轮已实现的调试单元、五个项目的产品复盘和下一步教学建议放在一起。此前确认的长期原则见 [产品上下文](PRODUCT_CONTEXT.md)，具体的 Lab 编写约定见 [能力单元设计](LAB_DESIGN.md)。

## 1. 用户确认的目标与提出的问题

> 我们的目标是让一个学生，在软件工程领域，从 0 分，走向 100 分。

0 分指近乎零基础。先让学生具备初级开发工程师的入职能力，再走向独立接手陌生系统和跨技术栈迁移。入职是中间里程碑。已有基础的学生可以从合适的位置进入，完成当前任务后离开，下次恢复原进度。

今天讨论先从题目重复与调试训练不足开始，随后追问这些要求能否在设计时一次想完整。调试单元改造完成后，又确认了本地部署状态，并把视角扩大到 xshow、Code Museum、Living World、Swarm Space 和 DevLabs。用户提出两个产品判断要检验：方向是否偏保守、与真实学生需求脱节，以及五个项目是否过于支离破碎。

本次讨论对“100 分”的建议定义是：面对陌生系统和不完整需求，学生能独立澄清问题、定位影响范围、交付可验证的改动，并在结果偏离预期时追查原因、负责修正。这是训练终点的行为描述，具体评价还需要用真实工程任务校准。

## 2. 09:30 后的 DevLabs 复查与实现

上午的代码复查发现，调试单元原有四题主要重复同一种缺陷；输入校验单元的四个训练位也仍围绕同一个函数契约。下一轮内容设计优先解决四件事：每个 Lab 训练不同的行为，学生能自己设计测试，帮助随熟练度递减，训练通过、独立变式和延迟表现分别验证。

用户要求把这些约束在设计阶段一起考虑，随后同意先改造整个调试单元。今后的能力单元一起定义目标、前置、任务递进、自主验证、帮助边界、独立验收、按薄弱概念补练和旧记录兼容。选中的单元要有完整闭环，MVP 可通过减少单元数量控制范围。题库用正确实现和代表性错误实现反向检查。约定已写入 [AGENTS.md](../AGENTS.md) 和 [LAB_DESIGN.md](LAB_DESIGN.md)。

### 已实现的“调试与回归验证”v2

| Lab | 缺陷 | 学生要拿出的证据 |
| --- | --- | --- |
| 0 | 门槛比较漏掉等于 | 从给定的边界反例起步，检验等于、低于和高于门槛。 |
| 1 | 循环内过早返回 | 自建多条记录，证明原函数漏算后续记录。 |
| 2 | 分组赋值覆盖旧值 | 构造同一分组重复出现的输入，验证结果应累加。 |
| 3 | 外部累计变量造成跨调用状态泄漏 | 在同一执行环境连续调用，用结果说明本次调用受前次影响。 |

学生先填写参数与预期结果，试运行对照初始缺陷代码和当前代码。平台核对预期，只保留能暴露初始缺陷的有效输入。修复后，正式验收同时执行隐藏检查和学生保留的回归用例。试运行支持查看调试输出，代码与反例表单一起保存。教师可以查看试运行、当时的代码和回归用例。

训练中提供三级按需提示。独立考核改用库存、作业、工时、发货等场景的字段与函数接口，关闭知识点、提示与自建试运行。失败后进行匹配补练。首次通过新版单元考核七天后开放延迟复测，复测失败后一天可以再测。延迟表现单独记录，原考核通过保留。

新版调试题使用独立的 v2 标识。旧题、草稿、历史成绩和原练习工程保留。其他单元尚未按这一样板全面改造。此次工程验收通过 53 项测试，并走查了桌面、手机上的学生和教师流程。**截至本次讨论，新版只在本机运行，尚未部署到远端，本轮改动也尚未提交推送。** [本机调试 v2 入口](http://127.0.0.1:4317/?lab=js-orders-debug-0-v2)

## 3. 五个项目各自承担什么

本轮复盘依据五个本地工作副本、README、部分实现、提交及已有远端跟踪记录。GitHub 网页未能直接读取。DevLabs 的评价包含当前本地调试 v2。

| 项目 | 现有可复用的能力 | 在成长路线里建议承担的任务 |
| --- | --- | --- |
| [xshow](https://github.com/glwang-g/xshow) | 电路拖拽与测量、逻辑和存储、CPU 执行与状态观察。 | 原理实验室。学生卡在状态传播、时序或执行过程时，可用一个短实验补上相应理解。 |
| [Code Museum](https://github.com/glwang-g/code-museum) | 语言谱系、同题比较、真实执行、草稿恢复。 | 语言比较与迁移实验室。用同一份要求和测试比较不同语言对同一个问题的处理。 |
| [Living World](https://github.com/glwang-g/living-world) | 权威世界规则、持续推进、快照和事件历史。 | 系统行为实验场。根据快照与事件复现故障，验证状态如何随行动改变。 |
| [Swarm Space](https://github.com/glwang-g/swarm-space) | 受限观察、Bot 意图、统一裁决、单步与对局回放。 | 进阶工程项目。练接口约束、策略比较、可重复实验和回归。 |
| [DevLabs](https://github.com/glwang-g/dev-labs) | 递进任务、真实执行、调试、自建反例、独立变式、学习日志和 Git 交付。 | 成长主线。组织当前任务、按需补练、工程成果、验证依据以及下一步。 |

xshow、Living World 和 Swarm Space 已有跨项目的世界契约，使用状态、行动、事件、快照和规则任务等共同概念。学生侧还缺一条可接续的路径，例如什么时候需要另一个实验、要带过去什么、实验结果回来如何用于完成当前项目。建议优先把这一段学生体验连起来。

## 4. 复盘判断与改进建议

1. **知识的组织顺序与学生的进入动机不同。** 从信号到机器很适合解释计算机。学生可能先想修好作业、做一个社团工具，或者弄懂 AI 为什么改坏了代码。用一个可以立即操作的问题开场，学生遇到具体困难时再补相关原理。之前 DevLabs 里缺少输入上下文、修改入口难找、做完不知道下一步，都是任务之间接不上带来的摩擦。
2. **当前验收比许多任务更接近真实工程。** 自建反例、检查失败原因、重跑回归、真实提交都应保留。工程阶段应让学生接手已有仓库，澄清不完整需求，判断影响范围，回应评审，处理需求变化并修复交付后的问题。首条入职路线应选定目标岗位，再用真实岗位说明和带教任务校准。国内校招样本已能看到业务开发、接口联调、数据库和协作等要求。 [校招样本一](https://jiuye.uestc.edu.cn/career/recruitment/onsite/g3xwjz717x1e) · [校招样本二](https://myjob.dlmu.edu.cn/campus/view/id/866965)
3. **支架需要逐渐退出。** 入门时给清晰情境和可运行的示例，之后把查资料、选验证方法和判断结果逐步交给学生。AI 可以从入门参与，但学生要对输出负责。早期可让 AI 提出解释，学生先预测再实测。进入工程后可以审查 AI 补丁、找反例、说明采纳依据。独立考核再用无平台帮助的变式验证。初学者理解和判断 AI 生成代码的困难本身就是可训练的能力。 [初学者理解 AI 生成代码的研究](https://arxiv.org/abs/2504.19037)

## 5. S0–S5 各阶段的交付结果（建议）

| 阶段 | 学生亲手交付的结果 |
| --- | --- |
| S0 程序认知 | 改一条可观察的规则，先预测变化，再运行验证。 |
| S1 语言应用 | 给已有小工具补功能，自建输入、修复错误并解释行为。 |
| S2 工程基础 | 接手小仓库，交出可运行、可复现、有测试和 Git 记录的改动。 |
| S3 AI 协作 | 用 AI 完成更复杂的工作，审查补丁，拒绝不合适的建议，给出验证依据。 |
| S4 企业工程实践 | 澄清需求、完成评审、应对变化并解决交付后的问题。在选定岗位的真实任务上校准初级入职能力。 |
| S5 技术栈迁移 | 在陌生栈中读懂项目、迁移一项功能、保持关键行为并说明技术取舍。 |

当前 DevLabs 已有 S0–S2 的本机 JavaScript MVP。表中的后续交付物是路线建议。每阶段允许按能力切入，用一项真实任务校准起点。能力图表示依赖与进展，项目成果、草稿与下一步任务共同构成恢复位置。

## 6. 下一轮优先验证一条纵向路线（建议）

候选项目是**社团活动报名与候补**，复用现有订单练习思路。学生首次打开就有可运行页面，先修好“最后一个名额”的边界问题。然后在同一仓库处理重复报名和取消递补，增加查询接口，提交改动并回应同学评审。最后选择一个接口迁到另一种技术栈，沿用原有测试验证行为。第一个跨项目接点可以是迁移时用 Code Museum 比较实现，其他实验围绕具体教学问题接入。

选取 5–8 名近乎零基础的学生做探索性试教。先看他们最近实际卡住的作业、小项目或 AI 生成代码，再观察样板中的三个结果：

- 首次能否做出一个看得见、自己能重复演示的成果。
- 卡住时能否理解反馈、找到下一步，并恢复原来的项目现场。
- 一周后能否在未见过的任务中复用同样的排查与验证方法。

先用这些观察决定哪里该补内容、哪里该改任务交接，再决定是否扩题库、统一引擎或扩大平台集成。现有测试和维护者体验反映工程质量，目标学生的需求与实际学习结果仍待试教观察。现有观察表、学习日志和教学流程可复用。 [试教说明](PILOT.md)
