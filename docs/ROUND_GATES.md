# 四轮递进与验收门槛

执行顺序：第一轮收口并验收 → 第二轮 → 第三轮 → 第四轮。后轮已有原型不能作为前轮完成的证据。

## 第一轮：关卡流程（工程验收通过）

本轮范围：共享合法状态转换；服务端记录进入、编辑、验收开始与结果、暂停；任务恢复；三种完成方式；自动前进取消；阶段全量通过后庆祝；继续与停留持久化；重复请求去重；中断验收恢复。

验收：自动测试必须覆盖非法转换、重复请求、中断、编辑失效。浏览器必须实际走过 S0 到 S1 的自动晋级、停留后刷新恢复和未完成关卡定位。本轮实际验收：完整回归 24 项通过，其中新增权威转换、请求去重、暂停编辑、中断恢复检查；独立浏览器走完 S0 自动进入 S1、S1 停留并刷新恢复、手机庆祝布局与未完成关卡定位。验收发现暂停后编辑不能恢复的问题，修正后回归通过。

本轮不宣称教学效果已经验证，不把第二轮实验原型计入第一轮完成。

## 第二轮：单关实验绑定（工程验收通过）

已将取消订单关卡的初始数据、预测、步进、回放和真实执行验收绑定。验收要求确定性、完整回放一致、分支隔离、预测证据可追溯，以及实际执行与教学规则的对照。

## 第三轮：S0–S2 世界变化（工程验收通过）

已将学生函数实际返回值、持久化读回数据及 HTTP 测试响应呈现在小店现场，保留来源摘要；历史任务进度与当前执行结果分开显示。

## 第四轮：真实试教（工具就绪，维护者体验待进行）

5–10 名真实学生，记录独立完成、卡点、变式、提示使用及延迟表现。先准备试教材料和观察表，实际试教需学员参与；自动测试和模型模拟不算试教结果。

## 本次逐轮收口记录

第二轮：取消订单关卡使用同一份 3800 分取消订单场景；真实 JavaScript 输出与规则步进结果比对，预测、代码摘要、规则版本及回放动作绑定到提交。浏览器实际验证该关场景和证据。

第三轮：小店展示函数真实测试输入及实际返回值，错误输出不会被正确答案替代。S2 保存实际读回的数据与 HTTP 测试响应，最终交付回归验证这些证据。浏览器实际验证错误金额到正确金额的变化，手机布局通过。所有服务状态均标明来自测试服务，不冒称常驻服务。

第四轮：观察记录、校验、导出、变式与延迟复测流程已准备；浏览器使用隔离测试夹具验证保存，不算真实试教。用户选择先由本人完整体验；该体验属于维护者体验测试，不据此推断零基础教学效果。待维护者记录实际问题并修正后，再招募零基础学员。
